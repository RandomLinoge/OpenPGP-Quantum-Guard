# Security policy

Do not report suspected vulnerabilities with real private keys, passphrases, encrypted confidential files, operational fingerprints, or GnuPG home archives.

Open a private GitHub security advisory and include the affected version, sanitized reproduction steps, expected behavior, observed behavior, and a disposable test fixture.

The project supports the latest tagged release. Experimental branches and locally modified builds are evaluated on a best-effort basis.

## Reporting console or CLI issues

Identify the interface, commit or tag, PowerShell edition and version, and GnuPG version. For a terminal issue, include the terminal host and the smallest sequence of keystrokes that reproduces it. For a CLI issue, replace identifying arguments and paths with synthetic values. Review standard output, standard error, screenshots, and recordings before attaching them. Use a fresh GnuPG home and a disposable identity when collecting evidence.
